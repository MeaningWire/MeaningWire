# MeaningWire 0.1.0-alpha.0

**DRAFT RELEASE-NOTES SOURCE — NOT PUBLISHED.** This source is intentionally stored without source-commit or artifact digests. The non-publishing publication preflight renders those machine-bound values from the exact verified candidate so the notes do not create a self-referential commit problem.

## What this release is

This is a proposed alpha preview of MeaningWire for evaluation, interoperability experimentation, and review of the public semantic-contract approach. It is not a production-readiness claim, stable compatibility promise, or evidence of real-vendor certification.

## Supported in this release

The proposed alpha surface includes registered JSON Schema Draft 2020-12 contract validation, schema and mapping registry inspection, the currently bounded deterministic mapping behavior, read-only JSON object and transactional JSON Lines reference adapters, the public CLI health/schema/proof commands, the pinned synthetic interoperability proof, deterministic release-candidate evidence, generated documentation references, and the current Starlight documentation experience.

## Added

The proposed alpha introduces MeaningWire's public project foundation; canonical envelope, reference, provenance, and authority primitives; the experimental Identity / Party contract; mapping and adapter foundations; deterministic validation and candidate evidence; transitional SPDX 2.3 SBOM evidence; generated reference documentation; accessibility/integrity checks; a worked architecture walkthrough; and an evidence-backed standards crosswalk.

## Changed

None relative to a previously published MeaningWire release because no versioned public MeaningWire release has yet been published.

## Fixed

Before this proposed preview, pre-release hardening corrected documentation link resolution and retained fail-closed diagnostics for intermittent Pagefind output divergence. These are candidate-development corrections, not fixes to an already published version.

## Breaking changes

None relative to a previously published MeaningWire release because there is no published predecessor. Experimental public contracts remain subject to the repository's documented pre-1.0 compatibility and migration policy.

## Migration guide

No migration from a prior published MeaningWire version is required. Evaluators should begin from this exact versioned artifact if and only if a public release is separately authorized and published.

## Security-relevant changes

The candidate process uses immutable GitHub Action pins, a hashed governed validation dependency lock, deterministic candidate/SBOM generation, official SPDX schema identity verification, project-specific SBOM validation, extracted-candidate verification, and a machine-readable release-readiness gate. Public signing or attestation is not implied by this source and remains separately gated.

## Compatibility statement

Canonical schemas, mapping definitions, mapping execution, CLI behavior, Adapter SDK behavior, release artifact/evidence formats, SBOM evidence, and the documented synthetic proof are covered only to the extent demonstrated by the repository's deterministic tests and exact candidate validation. The governed candidate target is GitHub-hosted Linux with CPython 3.12 and the locked Node/npm documentation toolchain. No universal operating-system, vendor, or external-standard compatibility is claimed.

## Known limitations

The current implementation is experimental and intentionally bounded. Mapping execution supports only the documented subset; reference adapters are read-only; no write-back, remote authentication, hosted service, vendor connector certification, broad real-world compatibility proof, public documentation deployment, package publication, or stable-contract guarantee is included. Accessibility work targets WCAG 2.2 AA, but formal conformance has not been claimed.

## Explicit non-claims

This proposed alpha is not a production-readiness certification, vendor certification, proof of universal interoperability, stable compatibility guarantee for experimental contracts, support-SLA commitment, security certification, or evidence of adoption. Checksums, SBOMs, provenance data, or future attestations do not by themselves prove that software is vulnerability-free or secure. A machine-readable `READY_FOR_HUMAN_DECISION` result would still not constitute human release authorization.

## Public implementation boundary

Supported MeaningWire behavior must remain understandable, buildable, testable, validated, and releasable from public MeaningWire source plus documented public dependencies. Private research may inform design, but a private MeaningWire codebase, hidden schema, private fixture, secret package, or undocumented MeaningWire service must not be required by the supported public artifact.

## Upgrade / rollback notes

Because there is no earlier public MeaningWire release, there is no published version to upgrade from or roll back to.
