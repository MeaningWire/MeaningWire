# MeaningWire RFCs

RFCs are used for substantial changes to public contracts, semantics, compatibility policy, governance, or architecture.

## When to write an RFC

Use an RFC when a proposal changes one or more of:

- canonical schemas or domain concepts;
- mapping relationship semantics;
- identifiers or versioning rules;
- provenance or authority behavior;
- event envelopes or public APIs;
- adapter SDK contracts;
- compatibility or deprecation policy;
- governance or release authority.

## Suggested structure

1. Summary
2. Problem and user need
3. Proposed design
4. Examples
5. Alternatives considered
6. Compatibility impact
7. Mapping loss / ambiguity
8. Provenance and authority impact
9. Security and privacy considerations
10. Accessibility considerations
11. Migration plan
12. Maturity target
13. Unresolved questions

RFC acceptance records project intent. It does not by itself make an implementation stable or released.
